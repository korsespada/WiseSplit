# Архитектура проекта

## Frontend Архитектура

Приложение построено как Single Page Application (SPA) с использованием Next.js App Router. Основной упор сделан на компонентный подход и разделение ответственности.

### Управление состоянием (State Management)

Для управления глобальным состоянием используется библиотека **Zustand**. Стор (`useStore`) является центральным местом для хранения и обработки данных.

**Основные срезы состояния:**
*   `user`: Текущий авторизованный пользователь (данные из Telegram/Supabase).
*   `currentGroup`: Данные активной группы, с которой работает пользователь.
*   `members`: Список участников текущей группы.
*   `expenses`: Список расходов текущей группы.
*   `userGroups`: Список всех групп пользователя.
*   `isLoading`: Флаг загрузки для UI индикации.

**Поток данных:**
1.  Компоненты подписываются на изменения в сторе через хук `useStore`.
2.  Действия пользователя (создание расхода, смена группы) вызывают методы стора (actions).
3.  Асинхронные методы стора (например, `fetchGroupData`) обращаются к Supabase API.
4.  При успешном ответе стор обновляет состояние, вызывая перерисовку компонентов.

### Маршрутизация

Используется файловая маршрутизация Next.js.
*   `/` (Home): Главная страница (Dashboard), где отображается список групп или детали выбранной группы.

## Backend Архитектура (Supabase)

В качестве Backend-as-a-Service (BaaS) используется Supabase, который предоставляет PostgreSQL базу данных, Auth и API.

### Аутентификация

Приложение рассчитано на использование внутри Telegram. В текущей реализации MVP используется сопоставление `Telegram User ID` с записью в таблице `users`.

### Безопасность (RLS - Row Level Security)

В Supabase включен RLS для таблиц.
*   *Текущее состояние*: Для удобства разработки включена политика "Public Access" (разрешено все всем).
*   *План*: Внедрить проверку `auth.uid()` и принадлежности пользователя к группе для ограничения доступа к данным.

### Взаимодействие с данными

Клиент Supabase (`lib/supabase.ts`) инициализируется публичным ключом и используется для прямых запросов к БД из браузера пользователя. Это позволяет избавиться от промежуточного API-слоя для большинства операций CRUD.
